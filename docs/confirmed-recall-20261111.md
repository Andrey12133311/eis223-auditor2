# Выявление пропущенных подтверждённых нарушений

Основа: `b75f9a9`, ветка `codex/procurement-legal-speed`, PR №112.
Цель: находить больше самостоятельных, подтверждаемых оригиналами нарушений
за счёт устранения пропусков извлечения и сопоставления фактов.

## Подход

Продолжается существующий конвейер FastAPI/SQLite и его юридические квалификаторы.
Исправляются воспроизведённые пропуски уже поддерживаемых правил. Новые свободные
оценки законности, изменение материально-правовых пределов и массовый перевод
неопределённых результатов в подтверждённые в этот пакет не входят.

### Воспроизведённые случаи

- Прямая сумма обеспечения с глаголом «равен» не становилась кандидатом.
- «Срок оплаты не превышает / составляет не более 15 рабочих дней» уже
  распознавался сборщиком условий, но не попадал в проверку нарушения.
- Полные подписи даты итогового протокола с «подведения итогов закупки»,
  решения об отмене «конкурентной закупки» и поступления запроса «заказчику»
  терялись в закрытых словарях событий.
- У одинаковых по байтам проверенных вложений дедупликация сохраняла другой
  UID только как источник-копию. Проверка XML события смотрела только основной
  UID и теряла подходящее подтверждение второго оригинала.
- Свежий проверенный XML извещения МСП присутствовал в контексте загрузчика,
  но не доходил до существующего квалификатора области закупки. Проверка
  обеспечения сохраняла неопределённость вместо применения подтверждённой
  области МСП.

Эти случаи воспроизведены на временных DOCX, SHA-квитанциях и ZIP/XML ЕИС;
они не являются установленными нарушениями в конкретных рабочих закупках.

## План и проверка

- [x] Добавить падающие регрессии для полных подписей дат и расширить только
  закрытые грамматические варианты, включая независимый парсер исторического срока.
- [x] Добавить падающие регрессии для обеспечения и верхних пределов оплаты;
  сохранить проверку НМЦД, области МСП, приёмки, пределов и конфликтующих условий.
- [x] Восстановить связь проверенных одинаковых оригиналов с XML события,
  заново проверяя квитанцию, SHA и область каждого поддерживающего источника.
- [x] Передать свежие данные извещения МСП через существующую структуру карточки
  в обе проверки; сохранить чистый квалификатор, конфликты и проверку редакций.
- [x] Проверить реальный общий/тематический путь, запись, повтор без дубля,
  счётчики и юридическую подпись. Добавить сборочные тесты.
- [x] Независимое ревью, полный набор unittest и необходимые Docker-проверки.
- [x] Подготовить проверенный пакет для PR №112 и будущей публикации.

## Результат контрольных оригиналов

Все перечисленные положительные случаи на исходной версии давали ноль
подтверждений. После исправлений каждый даёт одно подтверждение существующего
правила. Общий и тематический путь согласованы; повтор добавляет ноль новых
эпизодов, отображаемый счётчик контрольной закупки остаётся равным одному.

| Сценарий | Подтверждаемое правило |
| --- | --- |
| Прямое «размер обеспечения заявки … равен 100 000 руб.» при проверенной НМЦД 4 млн | Запрет обеспечения заявки при НМЦД до 5 млн |
| «Срок оплаты не превышает / составляет не более 15 рабочих дней» после приёмки, подтверждённая область МСП | Действующее правило предельного срока оплаты МСП |
| Подписание «протокола подведения итогов закупки» и проверенная публикация XML | Просрочка публикации протокола |
| Поступление «заказчику запроса» и проверенная цепочка разъяснения в XML | Просрочка разъяснения |
| Принятие/публикация решения об отмене «конкурентной закупки» | Просрочка публикации решения об отмене |
| Одинаковый оригинал под другим подтверждённым UID, связанным с XML протокола | Просрочка публикации протокола |
| Одинаковый оригинал под другим подтверждённым UID, связанным с XML разъяснения | Просрочка разъяснения |
| Тип текущего проверенного извещения МСП, НМЦД 10 млн и обеспечение 3% | Превышение двухпроцентного предела обеспечения МСП |

Правовые пределы и квалификаторы не изменены. Факт применения правила
проверяется исходными DOCX, квитанциями с SHA и неизменяемыми ZIP/XML.
Поддерживающий UID остаётся в доказательстве. Старые редакции, разные лоты,
неподтверждённые копии и конфликтующие события не выбираются ради подтверждения.

Текущая SOAP-карточка передаётся перед анализом через общий чистый адаптер
`merge_acquired_purchase`. Его семантика включена в юридическую подпись;
планировщик и SQLite writer в эту зависимость не включались. Квалификатор
области МСП остаётся чистым, дополнительных чтений XML в нём нет.

Новые наборы: `test_confirmed_event_recall` — 17 тестов,
`test_confirmed_amount_recall` — 10, `test_verified_source_recall` — 23.
Выборочные проверки: 243 теста событий, 188 денежных условий, 85 источников
и межпоточной согласованности прошли. Независимое ревью завершено.

Дополнительная Docker-проверка текущих исходников завершена: 50 новых тестов
за 8,046 с и 387 связанных регрессий за 80,401 с, без ошибок и пропусков.
Все 39 запусков прежних сборочных самотестов (37 различных скриптов, порядок
Dockerfile) прошли за 86,989 с. Использован ранее полностью собранный образ
`edc903aaa0e138ff8ad489d4f5d2634f8bd4268a6553d32a6f8d2454a9f89c8a`,
Python 3.12.16, SQLite 3.51.3; текущие `scripts/` и `tests/` подключены только
для чтения, сеть выключена. Все 473 SHA-256 Python-исходников совпали до и
после запуска внутри контейнера, а затем повторно на host. Это проверка
совместимости новых исходников в готовом окружении, без повторной сборки
всего образа; зависимости и схема запуска не изменились. Dockerfile дополнен
новым обязательным запуском всех трёх модулей регрессий.

Первый полный host-прогон выполнил 2 663 теста за 490,294 с, но три проверки
восстановления очереди не дождались целевой фазы в пределах 5 с. Он выполнялся
параллельно с Docker-проверкой: в одном случае инициализация до инвентаризации
заняла 3,215 с, рядом зафиксированы задержки event loop до 2,035 с. Отдельный
повтор всего `test_general_audit_recovery` прошёл: 22 теста за 15,437 с.
Код очереди и границы ожидания этих тестов не менялись. Итоговый полный прогон
без конкурирующей Docker-проверки завершился успешно: 2 663 теста за 445,270 с,
`OK (skipped=7)`. Все 50 новых регрессий выполнены; после предыдущего пакета
общее число добавленных регрессий составляет 81.

Отрицательные контроли: примеры и проекты, неизвестные источники, чужие лоты и
закупки, старые редакции, неподтверждённая область МСП, иной отсчёт оплаты,
ограниченные/альтернативные денежные формулы и противоречащие события.
