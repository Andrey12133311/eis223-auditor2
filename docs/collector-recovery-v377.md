# V377 — передача карточек и завершение загрузки оригиналов

Исходная версия: `53e08fa` (V376), ветка `thematic-audit-20261015`.

## Изменения

- Для точных машинных маршрутов передачи заказчика, цены и фактов карточки
  предварительный запрос браузера доходит до CORS. Сами запросы сохраняют
  проверку ключа загрузчика, официального Origin и содержимого.
- Задание загрузки завершается по сохранённым оригиналам, независимо от
  асинхронного юридического анализа, дедупликации и распаковки архивов.
  Ожидаемое число файлов берётся по максимуму карточки и серверного манифеста.
  Сохранение файлов не объявляется завершением проверки.
- Если DOCX содержит основной текст, но ссылается на отсутствующую
  вспомогательную часть, читается существующий основной XML с ограничением
  размера и запретом DTD/внешних сущностей. Оригинал не изменяется.
- Сохранившиеся старые записи с адресом ЕИС только в `docs.url` проходят
  проверку квитанции и SHA256. Логи ошибок содержат этап, тип и причину.

## Проверка

- 42 целевых Python-теста и 44 дополнительных случая прошли: метаданные,
  идентификация, хранилище, восстановление очереди и CORS/авторизация.
- Тесты JavaScript V377/V376 и DOM V314/V341 прошли.
- 36 из 37 самопроверок Dockerfile прошли локально; архивная V310 требует
  отсутствующий в локальной среде `bsdtar`. В Dockerfile эта утилита уже
  устанавливается пакетом `libarchive-tools`.
- Полный набор тестов кабинетов имеет те же 13 старых падений, что и чистая
  V376. Новых падений не появилось; целевые проверки gate проходят.

## Границы результата

Нужен повторный запуск браузерного загрузчика для перехода с V376 на V377.
Исправление серверного CORS действует также для уже работающей V376.
Статус юридического покрытия V295 не повышается по одному лишь числу
скачанных файлов. Недоступные оригиналы не считаются проверенными.
Точную причину ошибок старых документов по прежним кратким логам установить
нельзя; для оставшихся ошибок добавлена предметная диагностика.
Непроверенное прямое соединение Railway с ЕИС не включается.
