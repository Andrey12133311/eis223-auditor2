# Прямое получение ЕИС с VPS

Проверка предназначена для сервера, который будет получать документы ЕИС и
передавать их приложению. Она не запускает фоновые службы и не меняет настройки
операционной системы.

## Проверить связь с ЕИС

Запустите в консоли VPS Python 3:

```bash
python3 scripts/eis_vps_diagnose.py
```

Введите токен из личного кабинета потребителя машиночитаемых данных.
Он вводится скрыто и не записывается в исходный код или журнал.

Для физического лица применяется сервис
`https://int.zakupki.gov.ru/eis-integration/services/getDocsIP`, HTTP-заголовок
`individualPerson_token` и SOAP-запрос `getDocsByReestrNumberRequest` с
`subsystemType=RI223`. SOAPAction по WSDL:
`http://zakupki.gov.ru/fz44/queue/ws/get-docs-ip`.
Корневой элемент запроса имеет namespace
`http://zakupki.gov.ru/fz44/get-docs-ip/ws`, вложенные элементы — без namespace.
Адреса `getDocsMis2` и старого домена `int223` не являются
заменой этому контракту.

Основание: предоставленные официальные «Альбом ТФФ 16.3.1.zip»
(основной альбом, разделы 2.9.17 и 2.18, приложение 17) и
«Схемы 16.3.1 итерация 1.zip»
(`GetDocsWS/GetDocsIndividualPerson/getDocsIP-ws-api.xsd`,
`WSDL/WebServiceGetDocsIP.wsdl`).

HTTP 200 сам по себе не подтверждает подключение. Ответ должен соответствовать
SOAP-контракту, не содержать ошибки ЕИС и сообщать результат отбора либо
подготовки архивов. Получение метаданных XML ещё не подтверждает скачивание
оригиналов документации.

Если запрос останавливается до получения HTTP-ответа, по этому результату
нельзя судить о действительности токена. Для настройки TLS по 223-ФЗ нужно
учитывать раздел 2.18 альбома: обычный OpenSSL на VPS может не поддерживать
требуемые российские криптографические алгоритмы. Требование клиентского
сертификата не следует выводить из одного сброса соединения.

## Подключить постоянный загрузчик

После подтверждения связи с этого VPS: чтение очереди приложения, получение
SOAP-архивов, ожидание готовых частей, загрузка доступных оригиналов и передача
в существующие защищённые приёмники приложения. Ключ ЕИС и ключ приёмника
`EIS223_UPLOAD_TOKEN` имеют разные назначения.

Состояние фоновой службы и полный цикл получения реального документа нужно
проверить отдельно; диагностический скрипт этого не выполняет.
