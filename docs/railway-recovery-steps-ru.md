# Безопасное восстановление полной версии EIS 223

Railway отклоняет новые деплои до сборки с ошибкой `Complete result exceeds size limit`: конфигурация `web` содержит сотни переменных с программными патчами.

**Не удалять переменные с патчами до получения и проверки резервной копии. Не трогать подключённый том `/data`: там база закупок и документы.**

## Шаг 1. Сохранить собранную рабочую версию

Откройте Railway → проект `eis223-auditor` → сервис `web` → вкладка Console (если доступна). Выберите живой экземпляр (успешный деплой `27e6b49d-ef0d-44ee-9a06-ff7022bfae4c`), а не FAILED.

В консоли выполните одну команду:

```bash
python -c 'import urllib.request; exec(compile(urllib.request.urlopen("https://raw.githubusercontent.com/Andrey12133311/eis223-auditor2/4889ef1152001b83f0fcd087a60c54de1cd18415/scripts/railway_backup_runtime.py",timeout=30).read(),"backup_runtime.py","exec"))'
```

Ожидаемый результат: строки `SNAPSHOT_OK`, `PROGRAM_VARIABLES_SAVED`, `FILES_SAVED`, `PRIVATE_PATH`.

Скрипт сохраняет `/tmp/entry.py`, `/tmp/all_documents.py`, несекретные программные переменные, манифест и SHA-256 на **приватном подключённом диске** `/data/_eis223_runtime_recovery`. В GitHub эти данные не отправляются. База данных не меняется, сервис не перезапускается, содержимое переменных не печатается.

Если Console отсутствует, используйте Railway CLI SSH (`railway ssh -p <project> -s web -e production`) и ту же команду. Документация: https://docs.railway.com/cli/ssh

## Шаг 2. Только после подтверждения резервной копии

Сохранить текущую рабочую версию и токены; заменить исключительно заархивированные большие переменные программных патчей пустыми значениями. Не менять параметры подключения к источникам и хранилищу. Не очищать переменные до успешной проверки снимка.

## Шаг 3. Проверка нового запуска

В резервной ветке `repair-railway-config-20261009` находятся скрипты `scripts/railway_backup_runtime.py`, `scripts/railway_start_restored.py` и подготовленный Dockerfile.

Проверить запуск восстановленной версии и контрольные суммы, затем перенести изменения в `main` и задать `startCommand`:

```bash
python /app/scripts/railway_start_restored.py
```

Контроль: новый деплой SUCCESS, `/health` — HTTP 200, интерфейс и прежние проверки доступны, новые закупки и **доступные** документы обрабатываются. Недоступные источники не должны бесконечно занимать активную очередь.

**Не копировать `/data/_eis223_runtime_recovery` в публичный GitHub, так как резервная копия содержит внутренний программный код.**
