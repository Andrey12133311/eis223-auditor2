# Уточнение доказательств и ограничение работы с архивами

Рабочая основа: `c687b88`, ветка `fix/document-speed-legal-20261110`.
Сервис Railway `web` настроен на эту ветку; последняя успешная публикация
перед работой — `82f78d2`. Приложение запускается через
`scripts/railway_start_v282.py`; изменены модули действующего конвейера.

## Проверяемые изменения

- Извлечённый текст не выдаётся из кэша, если исходник изменился во время
  вычисления хеша, ожидания блокировки, чтения кэша или работы извлекателя.
  Замена или удаление файла означает неполное доказательство; следующая
  проверка получает текст из актуальных байтов. Неизменившиеся файлы сохраняют
  повторное использование кэша. Извлекатель читает проверенный разрешённый
  путь; смена цели символической ссылки не может подменить текст под старым хешем.
- Ограничения обработки архивов должны ограничивать фактически выполняемую
  распаковку, а не только размер сохранённого результата. Перечисление TAR
  получает общий бюджет, включая неподдерживаемые вложения во вложенных TAR.
  ZIP пропускает заведомо не помещающиеся файлы до распаковки. Неудачное
  чтение неизвестного размера также расходует бюджет. Прочитанный безопасный
  префикс TAR сохраняется с предупреждением о неполноте. Для libarchive
  сохраняются существующие таймауты; бюджет не является измерителем всей
  внутренней работы нативного распаковщика.
- Ограничение размера обеспечения в продолжении денежной формулы не должно
  исчезать после сокращения денежной единицы или разделителя.
- Даты запроса и ответа на разъяснение должны относиться к одному лоту как
  при первоначальном обнаружении, так и при оценке сохранённого кандидата.
  При повторной оценке заново подтверждаются публикация, её дата и просрочка.
  Отсутствующий, неоднозначный, изменённый или своевременный ответ не сохраняет
  прежнее подтверждение. Для ответа без даты в бинарном оригинале требуется
  актуальная проверка сохранённого SOAP XML и исходного файла; прежняя цитата
  XML в выводе доказательством не служит. Обычный текстовый путь не читает XML;
  проверяющая функция XML повторно используется в пределах одного вызова.

Нормативные пределы и права доступа не меняются. Исторические документы,
решения руководителей, базы и тома сохраняются. Синтетические тестовые
нарушения не включаются в рабочие счётчики.

## Проверка

Проверки используют временные файлы/базы и не отправляют документы на внешние сервисы.

`PYTHONPATH=scripts python scripts/benchmark_archive_expansion_budget.py --baseline c687b88`
сравнивает три прохода реальных синтетических архивов с новыми каталогами.

| Сценарий | До | После | Проверка результата |
| --- | ---: | ---: | --- |
| ZIP из 100 файлов по 1 MiB, лимит 72 MiB | 0,707219 с; 100 MiB распаковано | 0,540720 с; 72 MiB | Те же 72 документа, порядок, тексты и SHA; предупреждение сохранено |
| TAR.GZ с первым вложением сверх лимита | 0,195987 с; 76 562 432 байта | 0,000621 с; 16 384 байта | В обоих случаях неполный результат без читаемых документов |

Это измерение обработки локальных сверхлимитных архивов, а не скорости всего
сервиса или загрузки ЕИС. Обычные архивы проверяются отдельными регрессиями.

В исходном полном прогоне 2 582 тестов один тест не дождался фоновой проверки
за фиксированные 50 мс; отдельный прогон воспроизвёл два таких случая.
В `test_ingestion_review_revision` ожидание заменено проверкой фактического
состояния с ограничением 3 с. Те же 18 проверок прошли после исправления;
поведение приложения ради теста не менялось.

Сборочный `v353_unique_evidence_selftest` воспроизводимо падал и на чистом
`c687b88`: он ожидал удаления отдельного наблюдения оплаты по семантическому
сходству. Тест приведён к действующему договору журнала: разные точные ключи
доказательства сохраняют две записи, повтор той же записи добавляет ноль строк,
а семантическое объединение даёт одно юридическое событие. Самотесты v353/v342
и 29 тестов журналов прошли; реализация сохранения не менялась.

Положительная фикстура `test_vp_thematic_alignment` теперь явно указывает дату
публикации разъяснения в ЕИС. Ранее подставной анализатор объявлял нарушение
по неопределённому «Ответ размещён», которое фактический анализатор не считает
доказательством публикации в ЕИС. Исходная формулировка сохранена как отрицательный
пример; все прежние проверки тематической маршрутизации сохранены.

Финальный полный прогон:
`PYTHONPATH=scripts:tests python -m unittest discover -s tests` — 2 613 тестов
за 595,991 с, `OK (skipped=7)`. Все 31 новая регрессия выполнены.
Независимое ревью действующих модулей завершено без блокирующих замечаний.

Docker-проверка завершена: образ `eis223-legal-speed-20261111`,
SHA-256 `edc903aaa0e138ff8ad489d4f5d2634f8bd4268a6553d32a6f8d2454a9f89c8a`.
Выполнены все 53 исходные команды сборочных проверок; заключительный набор
из четырёх новых модулей — 31 тест, `OK`.

Для локального драйвера VFS и диска 32 GiB использован временный проверочный
Dockerfile: копирование тестов объединено, команды проверок выполнены в исходном
порядке в отдельных подоболочках одного слоя. Сами команды и исходники сохранены.
Доверенный сертификат прокси подключался временным секретом сборки. Эти адаптации
относятся к локальной проверке; исходный Dockerfile сохраняет обычную схему
сборки и дополнен четырьмя новыми тестовыми модулями.

Версия предназначена для существующего сервиса Railway `web` с его томом данных.
После размещения проверяются точный SHA коммита, статус публикации и `/health`.
