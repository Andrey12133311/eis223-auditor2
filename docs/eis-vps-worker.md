# Автоматический загрузчик ЕИС на VPS

Работник получает задания сайта, выполняет поиск по ИНН заказчика в ЕИС, запрашивает архивы через официальный SOAP-сервис ЕИС, передаёт XML на сайт и затем скачивает оригиналы по подтверждённым ссылкам из этих XML. Поиск, получение сведений о закупках и скачивание документов выполняются на VPS. Он работает как служба systemd на VPS с Ubuntu 24.04/26.04 и Python 3. Дополнительные Python-пакеты, открытые входящие порты и постоянно открытый браузер не нужны.

## Что происходит автоматически

- В версии 1.4.0 поиск по ИНН и общий просмотр используют общий сохранённый интервал 60 секунд вместо 300. Общий поиск запрашивает до 50 закупок на страницу вместо 20 и чередует первую страницу с последующими: 1, 2, 1, 3, …, 1, 10. Так новые публикации проверяются регулярно, а охват не ограничен первой страницей. Поиск по ИНН сохраняет до 20 номеров на страницу и до 10 страниц. Это ограниченная выдача: полнота всех публикаций не обещается.
- Найденные номера сначала становятся кандидатами. Заказчик подтверждается по полю `customer/mainInfo/inn` официального XML; поисковый фильтр сам по себе подтверждением не является. Закупки с другим ИНН заказчика исключаются из результатов. Сайт показывает ожидание проверки кандидатов и следующих страниц отдельно от завершения поиска.
- Общие поисковые кандидаты сохраняются отдельно от рабочей очереди и поступают в неё по мере освобождения мест. В рабочей очереди сохраняются восемь резервных мест для ручных запросов. Повторы не создают новые закупки и не увеличивают счётчики. Если постоянный список ожидающих кандидатов заполнен, сайт не подтверждает страницу: VPS сохраняет её и повторяет передачу позже.
- В версии 1.3.0 очередь опрашивается каждые 30 секунд вместо 300; за цикл выполняются до двух заданий. Каждое задание берётся непосредственно перед обработкой, чтобы аренда следующего не истекала во время большой закупки. Самостоятельные и тематические закупки получает из серверной очереди. Найденные поиском номера не помечаются самостоятельными.
- На один цикл — максимум 48 попыток загрузки оригиналов; между запросами файлов — не менее 2,5 секунды. Размер архива XML до 15 МиБ, отдельного оригинала до 25 МиБ.
- Неполученные оригиналы сохраняются в очереди, временные ошибки повторяются. При HTTP 403/429 — пауза не меньше 20 минут; более длинный `Retry-After` ЕИС или сайта соблюдается, включая дату HTTP. HTTP 503 также приостанавливает очередь. Пауза сохраняется при перезапуске. Блокировка поиска не мешает уже известным SOAP-заданиям.
- Оригиналы, которые сайт уже подтвердил, повторно не скачиваются. SQLite хранит скачанный, но ещё не переданный файл, отчёты до подтверждения сайта и состояние повторов. Архивы дополнительно дедуплицируются сайтом по SHA256.
- Отказ приёмника `422` для одного оригинала больше не останавливает остальные документы закупки. Непринятые байты удаляются только из кеша загрузки и при повторе скачиваются заново; подтверждённые документы сохраняются. Если отклонён XML-архив, закупка не объявляется полностью загруженной даже после доставки всех остальных известных документов.
- В версии 1.1.0 загрузка следующего оригинала совмещается с передачей предыдущего на сайт. Одновременно выполняется не более одного скачивания ЕИС; в памяти находятся текущий и максимум один следующий оригинал. Версия 1.3.0 увеличивает лимит цикла, сохраняя интервал 2,5 секунды и один поток скачивания. При ошибке передачи ожидающий запрос отменяется, а уже полученные байты сохраняются для повтора.
- Задания только на обновление карточки (`metadata_only`) передают XML без скачивания оригиналов и не расходуют лимит 48 оригиналов. Завершение такого задания подтверждает сервер после проверки архива и фактической записи сведений карточки; юридическая проверка этим не объявляется выполненной.
- После получения всех поддерживаемых оригиналов запускается проверка на сайте. Состояние `completed` у загрузчика означает доставку, а не завершённую юридическую проверку или найденное нарушение.
- Неизвестные ссылки, `contentUid` без подтверждённого адреса скачивания, блокировки и ошибки не превращаются в «успешно проверено».

## Установка

Сначала на сайте должно быть развёрнуто обновление с `/api/eis-worker/status`. Установщик проверяет версию API и оба защищённых соединения до изменения работающей службы.

Подготовьте два разных секрета:

1. Токен ЕИС из личного кабинета портала машиночитаемых данных.
2. Текущее значение `EIS223_UPLOAD_TOKEN`: Railway → проект `eis223-auditor` → служба `web` → `Variables`. Это ключ приёмника сайта. Не создавайте вместо него новый токен только на VPS: значения должны совпадать.

Секреты вводятся в скрытом приглашении установщика; в командную строку, переписку и Git их помещать не требуется.

Начиная с загрузчика 1.0.1, установщик проверяет каждый ключ до сетевого запроса. Если вставлены русские буквы, внутренние пробелы, невидимые символы либо само название `EIS223_UPLOAD_TOKEN`, он объясняет ошибку и повторяет ввод только этого поля. Скопируйте именно значение переменной; текст ключа при проверке не выводится.

Рабочий сайт использует режим `OFFICIAL_EIS_VPS_ONLY`: новые сведения, архивы и оригиналы принимает только от серверного загрузчика. Приём из браузерного загрузчика и ручные страницы загрузки отключены; старые ссылки на скрипт возвращают команду остановки. Уже открытый старый загрузчик перестанет передавать файлы на сайт; его вкладку можно закрыть. Поиск по номеру ЕИС и ИНН остаётся доступен на сайте и ставит задания VPS. Самостоятельные и тематические задания поступают в общую очередь VPS, а проверка сохранённых документов выполняется на сайте. При недоступности VPS автоматического переключения на браузер или Railway нет.

Из проверенной локальной копии репозитория:

```bash
sudo bash scripts/install_eis_vps_worker.sh --source-dir "$PWD"
```

Для загрузки неизменяемой версии из публичного репозитория установщик принимает `--revision` (полный 40-символьный Git SHA) и обязательный `--worker-sha256` (SHA256 файла `scripts/eis_vps_worker.py`). Конкретные значения предоставляет релиз. Не используйте подвижную ветку `main` вместо SHA и не отключайте проверку TLS.

По умолчанию установка ставит закупку `32616233661` первой для проверки соединения и передачи. Другой подтверждённый номер задаётся флагом `--bootstrap-reg`. Флаг `--site-url` задаёт HTTPS-адрес вашего сайта при первой настройке. При повторной установке сохранённые реквизиты используются автоматически; `--configure` повторно спрашивает оба токена.

## Обновление до 1.4.0

Ускоренный публичный поиск поддерживается загрузчиком **1.4.0**, быстрая очередь — начиная с 1.3.0, поиск по ИНН — с 1.2.0. Повторно запустите установщик с неизменяемой ревизией релиза и SHA256 нового работника, без `--configure`: он использует существующие ключи и сохраняет очередь файлов и отчётов. После проверки соединений установщик перезапустит службу.

Установщик меняет старый стандартный интервал 300 секунд на 30. Явный собственный интервал сохраняется; задать его можно через `--interval-seconds 60` (допустимы 30–3600 секунд). Чтобы явно включить быстрый режим при любом прежнем значении, используйте `--interval-seconds 30`. Ключи подключения, SQLite с очередью, файлы кеша и ожидающие отчёты сохраняются; `--configure` для обновления не нужен.

Для публичного поиска добавлен отдельный параметр `--search-interval-seconds 60` (30–3600 секунд). По умолчанию — 60 секунд; заданный ранее собственный интервал сохраняется. Поиск по ИНН и общий поиск делят этот интервал, а паузы источника и `Retry-After` могут его увеличивать. Уже сохранённая пауза не сбрасывается обновлением.

Развёртывание сайта само по себе не ускоряет установленную версию 1.3.0: в ней публичный поиск остаётся на 300 секундах. Для новых параметров требуется обновить службу VPS. При коротких заданиях и доступной ЕИС планировщик допускает до 60 страниц поиска в час вместо 12; это предел частоты, а не гарантия числа новых уникальных закупок или скачанных документов.

Интервал поиска — минимальная пауза между запросами. Загрузка большого документа, обработка очереди или ответ ЕИС могут увеличить фактический интервал. Полученная страница сохраняется на VPS до подтверждения сайта; после сбоя передачи повторный запрос страницы ЕИС не нужен.

При коротких заданиях внутренний потолок составляет 240 попыток закупки в час вместо 24. Это предел планировщика, а не обещание фактической скорости: время ответа ЕИС, размер документов, паузы источника и обработка на сайте уменьшают результат. Не увеличивайте число параллельных служб для обхода ограничений источника.

До обновления работники 1.0.1 и 1.1.0 продолжают получать задания по номерам закупок; задания по ИНН сохраняются в очереди. Сайт показывает необходимость обновления, пока активный VPS не сообщит возможность `inn_search`. Ошибочно отключённые предыдущей версией сайта запросы по ИНН возвращаются в очередь без дублирования активных запросов.

Установщик использует уже скачанный `/root/eis-ca.crt` либо официальный файл `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`. DER SHA256 сертификата закреплён в коде: `d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`. Сертификат применяется только к запросам ЕИС, системное хранилище доверия не меняется.

Служба выполняется от отдельного пользователя `eis223-worker`. Реквизиты находятся в `/etc/eis223-worker/credentials.json`, владелец `root:eis223-worker`, режим `0640`; состояние — в `/var/lib/eis223-worker`, режим `0700`. В systemd arguments и environment секретов нет.

## Проверка работы

```bash
systemctl status eis223-worker --no-pager
journalctl -u eis223-worker -n 25 --no-pager
```

При запуске событие `worker_started` показывает версию загрузчика, интервал очереди и лимит оригиналов; для быстрого режима ожидаются `version=1.4.0`, `interval_seconds=30`, `search_interval_seconds=60`, `originals_per_cycle=48`. В журнале выводятся только тип события, параметры скорости, номер закупки, счётчики и фиксированные коды ошибок. Токены, содержимое SOAP-ошибок и подписанные ссылки не выводятся. `report_ack/download_complete=true` подтверждает доставку по независимой проверке сайта. `delivery_attempt/requested_status` — предварительный результат работника, который сайт может понизить до неполного. `partial` означает, что часть оригиналов ожидает загрузки; `no_data` — ЕИС явно вернула `noData=true` либо полученные XML не содержат ссылок на оригиналы. Различие отражается в подробности отчёта сайта.

`discovery_status=blocked` означает, что публичный поиск ограничил серверный доступ. Работник не обходит CAPTCHA: сохраняет паузу и продолжает обработку известных номеров через официальный SOAP. Для гарантированного массового охвата потребуется отдельная интеграция с документированной периодической выгрузкой и согласованными параметрами охвата.

В журналах сайта `EIS_WORKER_TELEMETRY` показывает безопасные счётчики, состояния поиска и фиксированные коды ошибок; снимок при запуске включает последние 20 результатов заданий. `V294 ARCHIVE_REJECTED` и `V295 ORIGINAL_REJECTED` объясняют отказ проверки содержимого кодом причины. Наличие ответа HTTP 200 на heartbeat или отчёт не означает, что получен новый документ: фактическую доставку подтверждают `metadata_received`, `originals_received` и `download_complete`. Повторный архив (`duplicate=True`) не увеличивает количество новых закупок или оригиналов.

Загрузчик сообщает о себе сайту раз в минуту. Сервер выдаёт задания на 15 минут, heartbeat продлевает только текущую совпадающую аренду; потеря сети не теряет сохранённые отчёты.

Полезные команды:

```bash
systemctl restart eis223-worker
systemctl stop eis223-worker
systemctl start eis223-worker
```

## Коды ошибок

| Код | Смысл |
|---|---|
| `site_http_401` | Ключ сайта не совпадает с `EIS223_UPLOAD_TOKEN` |
| `eis_service_5`, `eis_service_24` | Токен отсутствует или неактивен по ответу ЕИС |
| `eis_http_403`, `eis_http_429`, `eis_service_13` | Ограничение доступа или частоты; пауза не менее 20 минут |
| `eis_service_8`, `eis_service_39` | ЕИС ещё готовит архив/обрабатывает запрос; повтор в следующем цикле |
| `eis_incomplete_response` | HTTP 200 не содержит ни ссылки, ни явного `noData`, ни распознанной ошибки; успешным ответ не считается |
| `eis_search_browser_challenge` | Поиску требуется проверка браузера; прямые SOAP-задания продолжаются |
| `unsupported_attachment_links` | Часть ссылок из XML приёмник пока не поддерживает; закупка остаётся частичной |
| `response_size_limit` | Превышен установленный предел размера ответа |
| `site_upload_not_accepted` | Сайт не подтвердил сохранение; исходный файл оставлен для повтора |

## Проверки разработчика

```bash
python3 -m unittest tests.test_eis_vps_worker -v
bash -n scripts/install_eis_vps_worker.sh
```

Тесты локальные: проверяют официальный XML-контракт с неквалифицированными дочерними полями, различение ошибок/отсутствия данных, ограничение редиректов, защиту XML/ZIP, дедупликацию, возобновление после сбоя, долговечность отчётов и честное состояние неполной доставки. Они не заменяют проверку работающей службы на VPS.

### Локальный замер конвейера 1.1.0

18 октября 2026 года: синтетические восемь оригиналов, пять прогонов, задержка скачивания и передачи по 30 мс, минимальный интервал начала скачиваний 25 мс. Это модель с масштабом времени 1:100, без запросов в ЕИС и без настоящих документов/реквизитов. Сравнение с кодом `19c77c2` (1.0.0): медиана 0,48668 с → 0,27571 с, на 43,35% меньше времени, ускорение 1,765×. Проверены одинаковые восемь переданных оригиналов и соблюдение интервала запросов.

Это сокращение активного времени передачи в локальной модели, а не измеренная скорость работающей службы. В этом историческом замере пределы составляли два задания и 12 оригиналов за пяти­минутный цикл; версия 1.3.0 меняет планирование, как описано выше. Реальный выигрыш зависит от времени ответа ЕИС, передачи на сайт и структуры очереди; требуется отдельный замер после установки версии 1.1.0 на VPS.
