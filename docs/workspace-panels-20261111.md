# Рабочий предпросмотр: боковые панели и компактные сценарии

Пользователь попросил попробовать все обсуждённые улучшения и показать результат. Реализовано поверх светлой темы из PR113, без изменения продуктивного Railway.

## Реализовано

- Левая панель шириной 220 px со сворачиванием до 68 px и сохранением предпочтения; существующие маршруты, отдельные пункты по ролям, профиль, раздел «Мой кабинет» и избранное.
- На узком экране меню становится модальным; поддержаны закрытие, Escape, Tab/Shift+Tab, inert фона и восстановление фокуса. В кабинетах, уже имеющих собственное меню, второй sidebar не добавляется.
- Правая панель до 460 px с вкладками «Сводка», «Замечания», «Документы»; обычный клик по закупке, выбор другой строки без потери фильтров/прокрутки, ссылка на полную карточку.
- Read-only GET существующей сохранённой карточки с текущей сессией. Новые endpoints, обходы авторизации и повторный запуск аудита отсутствуют.
- AbortController и порядковый номер запроса предотвращают показ старого ответа вместо новой закупки. Ошибки доступа/соединения очищают прежние данные, дают вход/повтор и сохраняют ссылку на полную карточку.
- HTML очищается структурно: без scripts/styles/forms/buttons/event-атрибутов/чужихID; только допустимые элементы и http(s)-ссылки без credentials. Важные предупреждения о неполных доказательствах, счётчиках и экспорте доступны в сводке и замечаниях.
- Краткая сводка полной карточки, раскрываемые реквизиты, раздельные состояния документов и юридической проверки, русское представление сохранённых дат без пересчёта времени/зон, мобильный список файлов с сохранённой семантикой таблицы.
- Закрепление существующих фильтров на компьютере; на коротких узких экранах закрепление отключено, чтобы форма не перекрывала закупки. Быстрые кнопки отражают только реальные варианты существующего select и применяют его существующей кнопкой. Нет вымышленных backend-фильтров.
- Копирование номера/ИНН и выравнивание сумм, меньше вложенных рамок в рабочем месте, монохромные SVG.
- Показатели руководителя — доступные кнопки перехода к реальным фильтрам. Просрочка использует серверный overdue, а не браузерную оценку дат. Добавлены точные пустые состояния, сброс фильтров и пояснение ограничения загруженного списка.

## Проверки

Основной набор: 96 unittest-проверок, OK, один существующий skip. v362_ui_auth_selftest и v364_eis_design_selftest — OK. Независимый review завершён, замечание о предупреждениях доказательств исправлено. Browserresults и фактические числа проверок сохраняются в results.json при запуске preview-инструмента; протестированы 209 сценариев, включая короткий экран 390×600 и мобильную кнопку закрытия. Дополнительно проверен автономный HTML без сетевых запросов; переключение «Телефон» в настольном браузере меняет ширину, а сенсорные размеры отдельно проверены в touch-контексте Chromium.

Браузерные сценарии включают смену закупки, устаревшие ответы, 401/503, недоверенный HTML, вкладки/раскрытие доказательств, role-навигацию, копирование, фильтры, клавиатуру, модальность/inert, сенсорные размеры, отсутствие переполнения и drill-down руководителя.

Как и на исходной версии, расширенные standalone-наборы v343_card_selftest, v345_thematic_fast_selftest и v351_capacity_selftest зависают по таймауту (15/45/45 сек соответственно при повторении на чистом live 82f). Это не выдаётся за пройденные проверки. Ранее зафиксированы такие же baseline-ограничения test_account_site_entry_v1/test_account_production_v1 — см. macos-interface-20261111.md. Backend по этим поводам не менялся.

## Предпросмотр

`tools/render_interface_preview.py` строит реальные страницы с полностью вымышленными данными, перехватывает все запросы локально и сохраняет снимки/проверки. Реестр — структурный макет закрытого runtime, остальные экраны используют действующие builders. `tools/export_interface_demo.py` упаковывает те же экраны/fixtures в один автономный HTML с переключением страниц и ширины. Адаптер данных существует только внутри артефакта, не добавляется в приложение.

```sh
PYTHONPATH=.:scripts python tools/render_interface_preview.py --output /tmp/eis-panels-preview
PYTHONPATH=.:scripts python tools/export_interface_demo.py --output /tmp/eis-panels-preview/preview.html
```

Для browsercheck нужны Playwright и /usr/bin/chromium; приложение не получает новых зависимостей.

Ни сайт, ни конфигурация Railway этим этапом не публиковались и не менялись. Перед возможным выпуском нужно согласовать его с параллельно изменявшимся server-source, описанным в предыдущем отчёте.
