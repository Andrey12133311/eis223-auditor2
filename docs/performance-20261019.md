# Отзывчивость сайта и очередь VPS — 19 октября 2026

## Наблюдавшиеся задержки

Перед изменением публичные `/health` и `/login` отвечали за 5,17–10,28 секунды
в трёх парах одновременных запросов. В HTTP-журнале Railway после 22:48 UTC
18 октября средний ответ `/api/v257/dashboard` составлял 11,36 секунды
(14 запросов); `/me/profile` — 21,47 секунды (8 запросов).
Несколько независимых запросов завершались одновременно после длительного
ожидания. CPU и память не достигали выделенных пределов.

## Изменения

- Проверка сессии в шлюзе выполняется в ограниченном пуле рабочих потоков.
  PostgreSQL не блокирует основной HTTP event loop. Проверенная учётная запись
  переиспользуется только внутри одного запроса; следующий запрос заново
  проверяет отзыв сессии, блокировку и роль.
- Соединения PostgreSQL переиспользуются через отдельный пул на процесс:
  минимум одно, максимум восемь, ожидание подключения/выдачи до пяти секунд.
  Сохраняются commit/rollback при выходе из контекстного менеджера.
- Тематические операции с БД и чтение/формирование карточки выполняются
  вне event loop. Одновременные старты сохраняют предел трёх активных очередей.
- Точные счётчики главной страницы кешируются по SHA256 всех участвующих
  полей доказательств. Смена текста, статуса, удаление и добавление строк
  учитываются при следующем чтении. Лимит кеша — 8192 отпечатка; в кеше
  остаются только отпечатки и числа, без исходного текста.

## Локальный замер счётчиков главной

Синтетическая база: 5000 закупок, 20000 нарушений, полные итоги по выборке
и первая страница из 100 закупок; медиана трёх запусков. Результаты одинаковы.

| Вариант | Время |
| --- | ---: |
| До изменения | 1,980 с |
| После, холодный кеш | 1,950 с |
| После, повторный запрос | 0,101 с |

Ускорение повторного расчёта — 19,7 раза. Это локальное измерение конкретной
операции, а не обещание мгновенной загрузки всех страниц в рабочей среде.

## Загрузчик 1.3.0

Интервал очереди уменьшен с 300 до 30 секунд; бюджет оригиналов за цикл
увеличен с 12 до 48. Два задания за цикл берутся по одному непосредственно
перед обработкой. Теоретический потолок коротких заданий — 240 попыток в час
вместо 24; реальная скорость зависит от ЕИС, размеров файлов и обработки сайта.
Один поток скачивания, расстояние 2,5 секунды между запросами файлов,
паузы HTTP/ЕИС и отдельный интервал HTML-поиска 300 секунд сохранены.

Обновление сайта не меняет исполняемый файл на VPS. Для включения нового
режима требуется один запуск установщика с неизменяемой ревизией и SHA256,
без `--configure`, с `--interval-seconds 30`. Ключи, очередь и кеш сохраняются.
Подробности — в `docs/eis-vps-worker.md`.
